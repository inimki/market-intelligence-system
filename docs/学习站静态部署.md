# 学习站静态部署与验收

学习站源码已包含在本仓库的 `learning-site/`。下载一个 ZIP 即可获得完整构建输入，
不再依赖仓库外的目录，也不需要 Sites / Cloudflare 账号。
页面仍通过现有 Nginx 的 `/learn/` 提供访问；运行时没有 Next.js / Node 服务。

## 1. 首次部署

1. 安装并启动 Docker Desktop（Linux 容器、WSL 2、虚拟化正常）。
2. 下载本仓库 ZIP 并解压，确认包含 `learning-site/package.json`。
3. Windows 双击根目录 `一键部署.cmd`。
4. 等待六个服务就绪，打开 http://127.0.0.1:8080/learn/ 。

首次部署自动生成本机随机凭据；AI Key 可选，不需要单独安装 Node 或 Python。
网络需可访问容器镜像、npm、Python 软件源及浏览器下载服务。
Linux/macOS 可复制 `.env.example` 为 `.env`（已有配置不要覆盖），
为数据库密码、n8n 加密密钥设置独立随机值，然后运行：

```bash
docker compose config --quiet
docker compose up -d --build --wait --wait-timeout 300
docker compose exec -T nginx nginx -t
```

不要分享完整的 `docker compose config` 输出，它可能包含展开后的密钥。

## 2. 旧版本升级

更新主仓库即可，今后 GitHub 学习站以本仓库目录为准。
已有 `.env` 若写了 `LEARNING_SITE_CONTEXT=../market-intel-learning-site`，
请只把该行改为 `LEARNING_SITE_CONTEXT=./learning-site`，保留全部密钥和数据库密码。
未设置该变量时，Compose 默认使用仓库内目录；自定义路径仍受支持。

仅更新学习站和 Nginx（其他服务已正常运行）：

```bash
docker compose build nginx
docker compose up -d --no-build --no-deps --wait --wait-timeout 90 nginx
docker compose exec -T nginx nginx -t
```

此操作短暂重启网页入口，不删除数据库、报告或 n8n 数据卷。
不要运行 `docker compose down -v`，也不要用新生成的凭据覆盖现有 `.env`。
仅 restart 不会重新生成学习页面。

## 3. 静态构建与备用部署

本机单独构建需 Node.js 22.13 或以上版本：

```bash
cd learning-site
npm ci
npm run lint
npm run build:static
npm audit
```

输出 `out/` 包含首页、404、CSS/JS、图标和分享图片，URL 前缀为 `/learn/`。
不可直接把 out 当作网站根路径 / 使用。
当 Node 容器镜像下载受限时，可在本机完成以上构建后，回到仓库根目录运行：

```bash
docker build -t market-intelligence-nginx:local -f deploy/nginx/Dockerfile.prebuilt learning-site/out
docker compose up -d --no-build --no-deps nginx
```

备用构建上下文必须是 `learning-site/out`，不能是整个仓库。
自定义分享图片域名可设置非敏感构建参数 `LEARNING_SITE_ORIGIN=https://example.com`。
仅接受 HTTP(S) origin，不允许账号密码、路径、查询参数；更改后需重建镜像。
它不会自动开通域名、HTTPS 或互联网访问。

## 4. 验收

Windows PowerShell 5.1 或 PowerShell 7：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/verify-learn.ps1
```

验证内容：/learn 跳转保留查询参数、HTML 和资源 200、MIME、缓存策略、
未知页面/资源 404、帮助页、原 API 健康和 /learning 路由隔离。
已有报告时可增加 `-VerifyLatestReport` 验证 HTML 预览和下载；
空数据库尚无报告时不要使用该参数。

只检查静态入口、未启动 API 的隔离容器可用：
`-BaseUrl http://127.0.0.1:18080 -SkipApi`。
这种隔离测试不代表整个业务系统已启动。

## 5. 发布与安全边界

- 学习站构建上下文采用允许清单；最终镜像只复制静态 out，不复制源码、依赖或密钥。
- 公开源码不含原个人托管配置；原独立 Sites 目录保留，不会被此版本修改或部署。
- Git 忽略 .env、数据库、日志、报告、依赖、构建缓存及个人托管状态。
- GitHub CI 验证 Python、Windows 初始化、学习站构建、依赖审计和密钥扫描。
- 当前端口仅绑定本机；发布 GitHub 代码不等于把业务平台开放到公网。
- 本轮发行验证记录见 [发布验收](发布验收-2026-09-10.md)。

依据：[Next.js 静态导出](https://nextjs.org/docs/app/guides/static-exports)、
[Nginx 路由](https://nginx.org/en/docs/http/ngx_http_core_module.html)。

# 一步一步理解市场情报系统

这份文档按“先看见结果，再深入代码”的顺序讲解。你不需要先掌握所有框架。

## 0. 先看最终结果

在项目目录执行：

```powershell
.\.venv\Scripts\Activate.ps1
market-intel demo --open
```

你会得到三个中间结果：

1. `data/market_intel.db`：结构化情报数据库。
2. `data/raw/run-xxxx/`：每次采集留下的原始证据。
3. `data/reports/market-intelligence-run-xxxx.html`：可阅读报告。

## 1. 信源配置进入系统

入口：`POST /api/sources`，数据模型在 `app/schemas.py::SourceConfig`。

信源分三种：

- `demo`：离线样例，用来学习和测试。
- `static`：普通公开网页，交给 Crawl4AI。
- `interactive`：需要点击或翻页的网页，交给 Browser Use。

系统不会让 LLM 自己决定采集所有网站；你明确登记的网站才会进入采集队列。

## 2. n8n 发起一次运行

n8n 的定时器每天 08:00 调用：

```text
POST /api/runs
```

FastAPI 入口在 `app/main.py`，它调用 `MarketIntelligencePipeline.run()`。
手动运行和定时运行走同一条代码路径，因此测试结果与上线逻辑一致。
运行历史可以通过 `GET /api/runs` 查看。

## 3. 路由选择正确采集器

`app/collectors/router.py` 根据 `source.kind` 选择：

```text
demo        → DemoCollector
static      → Crawl4AICollector
interactive → BrowserUseCollector
```

在 Docker 部署中，API 会把真实网页任务发到独立 Collector 服务，避免浏览器依赖污染主服务。

## 4. Crawl4AI 得到网页正文

`app/collectors/crawl4ai_collector.py` 的核心是：

```python
result = await crawler.arun(url=str(source.url), config=config)
```

它输出标题、Markdown 正文、最终 URL、HTML 和页面元数据。这里的职责只有“把网页变成可处理文本”。

## 5. Browser Use 处理交互页面

`app/collectors/browser_use_collector.py` 给浏览器代理一个受限制任务：

- 只允许目标域名；
- 阻止直接访问 IP；
- 禁止下载；
- 最多 10 步；
- 不允许提交、购买、发布或修改账户；
- 最终返回固定 JSON。

它适合翻页和筛选，不适合绕过验证码、访问控制或付费墙。

## 6. 保存原始证据

`app/evidence.py` 在标准化之前保存：

- JSON：来源、标题、正文、时间、采集元数据；
- HTML：Crawl4AI 返回原始 HTML 时额外保存。

这样报告有疑问时可以回到当次采集证据，而不是只剩一段 LLM 摘要。

## 7. 标准化与去重

`app/normalization.py` 做四件事：

1. 清理多余空白。
2. 删除 URL 中 `utm_*`、`spm` 等追踪参数。
3. 对“标题 + 正文”计算 SHA-256。
4. 提取简短摘要和原文证据句。

数据库唯一键是：

```text
canonical_url + content_hash
```

同一 URL 同一内容不会重复入库；同一 URL 内容发生变化会保留为新版本。

## 8. 确定性分析

`app/analysis.py::DeterministicAnalyzer` 使用 Pandas 计算：

- 去重后情报数；
- 信源数量和信源分布；
- 每日数量；
- 高频主题；
- 可复算摘要。

这些数字不交给 LLM，避免同一批数据问两次得到不同答案。

## 9. PandasAI 探索性问数

当你调用 `POST /api/analysis/ask` 时，API 把已入库数据发给独立 Analysis 服务。

Analysis 服务从 `.env` 读取通用的 `AI_PROVIDER`、`AI_API_KEY`、`AI_BASE_URL` 和
`AI_MODEL`。当前默认通过 LiteLLM 接入 DeepSeek，模型为 `deepseek-v4-flash`；以后也可以
只改配置切换其他兼容供应商，而不改数据处理流程。

适合的问题：

```text
哪些竞争对手同时提到了节能和预测性维护？
```

它只用于探索，不替代报告中的固定指标。由于 PandasAI 会生成并执行代码，服务被放进只读、低权限容器。

## 10. 生成报告

`app/reporting.py` 把分析结果交给 `app/templates/report.html.j2`，生成自包含 HTML：

- 总览数字；
- 本期摘要；
- 信源分布；
- 高频主题；
- 每条情报、原文证据和来源链接。

报告不依赖在线图表库，离线打开也能阅读。

## 11. 你以后最值得改造的地方

按价值排序：

1. 在 `SourceConfig` 增加每个网站专用提取规则和质量门槛。
2. 增加“发布时间缺失、正文过短、异常激增”的数据质量告警。
3. 把关键词计数升级为公司、产品、地区、价格、动作等实体抽取。
4. 增加跨期变化：新品、涨价、渠道扩张、招聘变化。
5. 在 n8n 成功分支连接企业微信、飞书或邮件。
6. 加入登录认证、HTTPS、备份和监控后再对公网开放。

## 12. 上线前的验收清单

- 连续运行两次，第二次不重复入库。
- 随机抽查至少 10 条报告结论，均能回到来源和原始证据。
- 目标网站改版后采集失败会告警，不会静默生成错误报告。
- API Key 只在 `.env` 或 n8n Credentials 中，不进入 Git。
- PostgreSQL 不直接暴露公网。
- Browser Use 不允许跨域、提交和购买。
- PandasAI 与主 API 分开运行。
- 数据库、原始证据和报告都有备份。

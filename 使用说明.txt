市场情报平台：从下载到运行（Windows 一键部署版）

1. 先准备一次环境
安装并启动 Docker Desktop，选择 Linux 容器 / WSL 2 后端。
官方安装说明：https://docs.docker.com/desktop/setup/install/windows-install/
如果要求启用虚拟化、安装 WSL 或重启 Windows，请先完成。
建议 4 核 CPU、16 GB 内存、15 GB 以上空闲磁盘。
使用 Docker 时不需要另外安装 Python、Nginx、PostgreSQL 或 Node.js。
确认 Docker Desktop 显示 Engine running。

2. 下载并解压
项目：https://github.com/inimki/market-intelligence-system
点击 Code → Download ZIP，解压到普通文件夹，不要在压缩包中运行。
学习站源码已包含在 learning-site 文件夹，无需另行下载或注册云端托管账号。
若已安装 Git，也可执行：
git clone https://github.com/inimki/market-intelligence-system.git

3. 双击“一键部署.cmd”
首次会自动生成 .env、数据库随机密码与 n8n 随机加密密钥。
自动下载镜像、安装组件、启动六个服务、添加示例信源、导入和发布 n8n 工作流。
第一次构建需要网络，可能持续十几分钟或更久；请等待日志显示 Ready。
完成后自动打开网页。失败时窗口会显示具体原因。
无需手动复制 .env，也无需先申请 AI Key。
已有 .env 会保留，脚本不会更换你之前保存的 Key 或数据库密码。

4. 打开平台
平台首页：http://127.0.0.1:8080/
源码学习站：http://127.0.0.1:8080/learn/
浏览器图文指南：http://127.0.0.1:8080/help
API 操作页：http://127.0.0.1:8080/api/docs
最新报告：http://127.0.0.1:8080/reports/latest
n8n 管理页：http://127.0.0.1:5678/
第一次进入 n8n，需要自行创建管理账号。未生成报告时最新报告链接暂时不可用。
Nginx 提供网页统一入口，实际采集和报告功能由 Python 应用完成。

5. 生成报告
打开首页，点击“新建市场调研”。
行业示例：储能。
公司示例：宁德时代、阳光电源（最多 8 家）。
关注主题示例：新品、产能、订单。
点击“搜索并生成报告”，等待完成后在线浏览或下载 HTML。
普通公开网页采集和统计报告不要求 AI Key。
搜索或采集受网络、网页结构及网站访问许可影响，必要时手动添加官方信源。

6. 可选：配置 DeepSeek、OpenAI 或其他 AI 服务
用记事本打开项目根目录的 .env，找到并修改原来的四项；不要重复添加多套配置。

DeepSeek：
AI_PROVIDER=deepseek
AI_API_KEY=你的DeepSeek_Key
AI_BASE_URL=https://api.deepseek.com
AI_MODEL=deepseek-v4-flash

OpenAI：
AI_PROVIDER=openai
AI_API_KEY=你的OpenAI_Key
AI_BASE_URL=https://api.openai.com/v1
AI_MODEL=你账户当前可用的模型ID

其他 OpenAI 兼容服务：
AI_PROVIDER=openai
AI_API_KEY=该服务商的Key
AI_BASE_URL=服务商文档提供的兼容接口地址
AI_MODEL=服务商支持的模型ID

模型要支持所用的工具调用/结构化输出，并非每家兼容接口都已经测试。
模型名称及权限以各家官方控制台为准。
可另外填写 BROWSER_USE_API_KEY，给 Browser Use 使用独立云服务。
没有任何 AI Key 时，Browser Use 交互采集和 PandasAI 问答不可用，基础报告仍可用。

保存后再次双击“一键部署.cmd”，或在项目目录的 PowerShell 执行：
docker compose up -d collector analysis
注意：仅 restart 不会更新容器环境变量。

本机 .env 不会上传 GitHub，也不提供作者的 Key。使用者自行承担模型 API 费用。
不要把 Key、.env 或数据库密码放入截图、公开聊天或 Git 仓库。

7. 日常使用
启动：再次双击“一键部署.cmd”，会检查并启动服务。
停止但保留数据：docker compose stop
启动已有容器：docker compose start
查看状态：docker compose ps
应看到 nginx、postgres、api、collector、analysis、n8n 六个服务正常运行。
API 的 8000 端口保留用于本地调试；日常通过 Nginx 的 8080 端口使用。

8. 更新
通过 Git 下载：先备份数据，执行 git pull，然后双击“一键部署.cmd”。
通过 ZIP 下载：将新版代码放回原项目目录，保留原 .env 和目录名，再次部署。
首次安装后不要随意更改 POSTGRES_PASSWORD 和 N8N_ENCRYPTION_KEY。
不要执行 docker compose down -v，-v 会删除数据库与报告等数据卷。
Docker Desktop 必须保持运行；没有本机环境就不能使用 127.0.0.1 地址。

9. 排错
Docker 未找到：安装 Docker Desktop，重新打开终端或重启电脑后再运行。
虚拟化未启用：按电脑厂商说明在 BIOS/UEFI 开启虚拟化，完成 WSL 2 配置。
镜像或依赖下载失败：检查网络与镜像源可达性，修复后再次双击。
8080 占用：在 .env 添加 WEB_PORT=8081，再次双击，改用 http://127.0.0.1:8081。
8000/5678 占用：关闭占用程序；不要同时启动旧版 Python 本地服务。
网页 502：执行 docker compose logs --tail 80 nginx api。
AI 报错：检查 Key、余额、接口地址与模型权限，然后重新创建 collector/analysis 容器。
没有调研结果：检查目标网页是否可达，换公司全称或手动添加允许采集的官网信源。
密钥配置检查可运行 scripts 中的“检查运行环境.ps1”；英文 PASS 为通过，WARN 为提醒。

10. 适用范围
一键入口已针对 Windows Docker Desktop 设计；Linux/macOS 手动路线见 README。
默认只向本机开放网页，Nginx 不会自动让网站上线互联网。
公开上线需要另配域名、HTTPS、登录认证和备份。
只采集允许访问的内容，遵守网站规则，不绕过验证码、付费墙或访问控制。
项目的原创代码采用 MIT；第三方组件各自保留许可证，n8n 有单独的使用条款。
详见 THIRD_PARTY_NOTICES.md、PRIVACY_AND_COMPLIANCE.md 和 SECURITY.md。
